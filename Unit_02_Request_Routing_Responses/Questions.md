# Unit 2 Question Bank: Request, Routing & Responses

## 2-Mark Questions

### Q1. What is route prefixing in Laravel? Provide an example.
**Answer:** Route prefixing groups routes under a common URI path. E.g., prefixing a group with `'admin'` groups all child paths under `/admin`:
```php
Route::prefix('admin')->group(function () {
    Route::get('/users', function () { ... }); // Matches /admin/users
});
```

### Q2. How do you define an optional parameter in a route?
**Answer:** Append a `?` to the parameter name and assign a default value to the corresponding variable in your route closure or controller method:
```php
Route::get('/user/{name?}', function ($name = 'Guest') { ... });
```

### Q3. Explain the difference between `url()->current()` and `url()->full()`.
**Answer:**
*   `url()->current()` returns the current URL *without* query parameters (e.g., `http://test.com/profile`).
*   `url()->full()` returns the entire URL *including* query parameters (e.g., `http://test.com/profile?ref=google`).

### Q4. Write code to return a JSON response with status 404 in Laravel.
**Answer:**
```php
return response()->json([
    'error' => 'Resource not found'
], 404);
```

### Q5. What is the default cookie encryption behavior in Laravel?
**Answer:** By default, all cookies generated by Laravel are encrypted and signed with the application encryption key (`APP_KEY`) so that they cannot be read or modified by the client.

## 5-Mark Questions

### Q6. Detail the role of Middleware in the Laravel Request Lifecycle.
**Answer:**
Middleware acts as intermediate request filters in a Laravel application. They sit between the routing engine and the controller actions:

1.  **Request Filtration**: When a request matches a route, it passes through a list of assigned middleware classes sequentially.
2.  **Inbound Operations**: Middleware can inspect header credentials, check session parameters, and block unauthorized users before they hit the controller. For example, the `auth` middleware redirects guest users to the login route.
3.  **Outbound Operations**: After the controller executes and outputs a response, middleware can modify response headers, compress content, or clean cookies before sending the payload back to the browser.
4.  **Registration**: Middleware is registered inside `bootstrap/app.php` or `app/Http/Kernel.php` and applied to routes using `->middleware('name')`.

### Q7. Explain Route Constraints. Provide route syntax examples demonstrating:
1.  **Strict numeric constraint on an ID.**
2.  **Strict alphabetic constraint on a name.**
3.  **Dashed lowercase constraint on a slug.**

**Answer:**
Route constraints use regular expressions to validate that URL parameters match specific formats. If a parameter doesn't match the constraint, the route engine throws a 404 HTTP error.

#### 1. Strict numeric constraint (digits only):
```php
Route::get('/user/{id}', function ($id) {
    return "User: " . $id;
})->where('id', '[0-9]+');
```

#### 2. Strict alphabetic constraint (letters only):
```php
Route::get('/user/{name}', function ($name) {
    return "Name: " . $name;
})->where('name', '[A-Za-z]+');
```

#### 3. Dashed lowercase constraint (slugs):
```php
Route::get('/blog/{slug}', function ($slug) {
    return "Slug: " . $slug;
})->where('slug', '[a-z-]+');
```

### Q8. Discuss different methods of passing data from a Controller to a Blade view in Laravel, with code examples.
**Answer:**
Laravel supports several ways to pass variables to views:

1.  **Associative Array Method**:
    ```php
    public function show() {
        return view('profile', [
            'name' => 'John Doe',
            'email' => 'john@example.com'
        ]);
    }
    ```
    *Inside View*: Access via `{{ $name }}` and `{{ $email }}`.

2.  **The `with()` Method**:
    ```php
    public function show() {
        return view('profile')
                ->with('name', 'John Doe')
                ->with('email', 'john@example.com');
    }
    ```

3.  **The `compact()` Method (Standard Best Practice)**:
    ```php
    public function show() {
        $name = 'John Doe';
        $email = 'john@example.com';
        return view('profile', compact('name', 'email'));
    }
    ```
    The `compact()` function creates an associative array using the variable names as keys.

## 10-Mark Questions

### Q9. Detail the full range of Laravel HTTP Response options. Write code examples showing how to configure headers, encrypt cookies, return JSON, download files, and redirect to named routes with flash messages.
**Answer:**
Laravel's response system allows developers to control all HTTP headers, status codes, cookies, and payloads returned to clients.

#### 1. Custom Content, Status & Headers:
```php
public function customResponse() {
    return response('Plain Text Content', 200)
                ->header('Content-Type', 'text/plain')
                ->header('Cache-Control', 'no-store')
                ->withHeaders([
                    'X-Header-One' => 'Val1',
                    'X-Header-Two' => 'Val2'
                ]);
}
```

#### 2. Encrypting Cookies:
Cookies attached to the response are encrypted automatically by the framework:
```php
public function setCookie() {
    return response('Cookie Set Successfully')
                ->cookie('remember_token', 'secure_hash', 60); // 60 minutes
}
```

#### 3. JSON API Response:
Ensures the client receives a properly formatted JSON payload and the header `Content-Type: application/json` is attached:
```php
public function getJson() {
    return response()->json([
        'success' => true,
        'data' => ['id' => 45, 'role' => 'editor']
    ], 200);
}
```

#### 4. File Downloads:
Triggers browser download prompts using local files:
```php
public function downloadReport() {
    $path = storage_path('app/reports/report_2026.pdf');
    return response()->download($path, 'Annual_Report.pdf');
}
```

#### 5. Redirects to Named Routes with Flash Session Message:
```php
public function updateProfile() {
    // Process profile update logic here...
    
    return redirect()
                ->route('dashboard')
                ->with('success', 'Your profile details have been successfully saved!');
}
```
*Blade Check inside dashboard view*:
```blade
@if(session('success'))
    <div class="alert alert-success">{{ session('success') }}</div>
@endif
```
